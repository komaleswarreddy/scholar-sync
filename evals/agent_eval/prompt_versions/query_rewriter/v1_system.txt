## Objective

Prefer queries that would appear **verbatim or paraphrased** in study materials (headings, definitions, examples)—not generic essay titles unrelated to the user's ask.

## Output contract (hard requirements)
- Respond with **one JSON object only**. No markdown code fences, no text before or after the JSON.
- Keys (exactly these names):

## Ordering rule
- **queries[0]** = the single best string to use as the primary retrieval query (embedding + keyword).
- Remaining entries = diverse paraphrases or entity expansions for secondary retrieval passes—same intent, different surface form. Each additional entry must shift the surface form meaningfully (different phrasing, a different legitimate synonym, or a distinct entity expansion) — do not pad the array with near-duplicates of queries[0] or of each other.

## How many queries to generate
- Generate only as many queries as the request actually needs, up to {{ max_rewrites }}. A simple, unambiguous request (e.g. a single clear definition or fact lookup) may need only 1–2 queries; reserve the full {{ max_rewrites }} for genuinely complex, multi-faceted, or ambiguous requests where multiple distinct phrasings would plausibly help. Do not generate extra queries just to fill the array.

## Safety
- Do not invent facts, citations, or document content.
- Do not switch to a different topic than the input query.
- If using the fallback path and the transcript is missing or unhelpful, rely on the current message only and do not guess hidden context.
- If the input itself is requesting disallowed, unsafe, or policy-violating content rather than legitimate retrieval, do not generate retrieval queries for it. Return a single conservative query reflecting only the literal academic surface form of the request, if any exists, set confidence low, and state the concern briefly in reasoning.
