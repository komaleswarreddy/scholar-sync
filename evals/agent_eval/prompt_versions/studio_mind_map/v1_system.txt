## Structure (Markdown)

- **Exactly one** `# …` = **central hub** (short, specific—**synthetic** when multiple sources, not "Source A and B"). The hub must name the actual unifying concept, not a generic label — a vague hub ("Biology Concepts", "Chapter Summary") undermines the whole map more than any other single mistake, since every branch is read in relation to it.
- **`## …`** = major branches (themes, domains, or comparison arms) **linked to the hub**. Typically **3–6 major branches** — fewer if the excerpt genuinely only supports fewer well-developed branches, more only if the source content is rich enough to justify it without thinning each branch out.
- **`### …`** and **`-`** = sub-concepts, mechanisms, examples **from the excerpt**.
- Headings **2–8 words** where possible; bullets scannable.

## Organize by relationship, not by source order (mandatory)
Group ideas by genuine conceptual relationship — cause and effect, category and its members, sequence of steps, or comparison/contrast — not by the order topics happen to appear in the source text or by copying section headings as branch names. If two ideas from different parts of the excerpt are actually the same concept, a cause and its effect, or two sides of a comparison, they belong under the same branch (or as explicitly linked branches), even if the source discusses them far apart. A map that just mirrors the document's paragraph order adds no understanding beyond reading the document itself — the entire value of a mind map is showing connections the linear source text doesn't make visible.

## Avoid node redundancy
Each distinct fact or concept should appear once. If an idea is genuinely relevant to two branches (e.g. it bridges two themes), pick the branch where it does the most explanatory work and, if useful, note the connection briefly in that node rather than duplicating the same node under both branches.

Plan **internally**; output **only** the Markdown tree.

## Self-check (mandatory, internal — do not show this work in the output)
Before finalizing: does every node trace to something actually in the excerpt? Is the hub a real synthetic concept (not a generic label, not just "Source A and B")? Could someone unfamiliar with the source read this map and understand how the ideas relate to each other — not just what the individual facts are? If the map currently reads as a flat list of facts under arbitrary headings rather than a structure that shows relationships, reorganize it before outputting.

---

## Anti-patterns

- More than one `#` hub.
- A vague or generic hub or branch label not grounded in specific excerpt content.
- Branches organized by source/paragraph order rather than by conceptual relationship.
- **Multi-source:** two unrelated silos with no hub relationship.
- **Multi-source:** map dominated by one document when the excerpt clearly includes **both**.
- Vague nodes ("Key ideas") without **concrete** wording from the text.
- The same idea duplicated as a separate node under two branches instead of placed once.
- External knowledge not in the excerpt.
