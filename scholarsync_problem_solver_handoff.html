Guided Problem Solver: Step 3 Solving Mode Selector

Implement a direction-first problem-solving workflow where students upload a question, receive Problem DNA analysis, then choose the kind of help they want. The system should reduce blank-chat friction and produce mode-specific RAG responses.

Text · Image · PDF · Doc input Problem DNA before solving 4 solving modes Only one mode is lightly interactive
01 · Product Goal

What this feature should achieve

Students preparing for 11th/12th and competitive exams often know they need help, but do not know what exact prompt to ask. This selector converts vague intent into structured RAG behavior.

Core Product Intent

Do not drop the student into a blank chat after upload. First analyze the problem, then let the student choose a solving style. Based on that choice, the RAG/Tutor agent should give a complete, useful response.

Important Constraint

Do not expect students to submit full algebraic working or long equation-heavy solutions. Most flows should be one-directional. Only Help Me Solve It may ask for student input, capped at maximum 2 small inputs.

Implementation principle: Step 3 is not a diagnosis form. It is a Solving Mode Selector that controls prompt template, answer structure, reveal behavior, follow-up buttons, and interaction limit.
02 · Locked Decision

Final 4 solving modes

Use these exact labels unless design decides minor wording changes later. Intent should remain unchanged.

Mode 1

Explain from the Basics

Break down the problem from the beginning and explain every step clearly.

  • Best when student cannot start
  • Gives full structured solution
  • No student input required
Mode 2 · Recommended

Help Me Solve It

Guide with hints and small checkpoints without giving the answer immediately.

  • Best learning-first mode
  • Maximum 2 small inputs
  • Then complete or offer reveal
Mode 3

Show the Missing Idea

Reveal the key observation, concept, or trick needed to unlock the problem.

  • Best when student knows topic
  • No full solution by default
  • Focus on insight
Mode 4

Show the Best Approach

Show the most reliable and efficient way to solve this problem for exams.

  • Not shortcut-only
  • Reliable method first
  • Exam usefulness included

06 · RAG Behavior

Prompt and response control

Mode selection should be passed to the backend and used to choose the system/developer prompt template.

type SolvingMode =
  | "EXPLAIN_FROM_BASICS"
  | "HELP_ME_SOLVE_IT"
  | "SHOW_MISSING_IDEA"
  | "SHOW_BEST_APPROACH";

interface ProblemDNA {
  subject?: string;
  chapter?: string;
  conceptTags: string[];
  difficulty: "Easy" | "Medium" | "Hard" | "Unknown";
  expectedTimeMinutes?: number;
  questionType?: "Numerical" | "Conceptual" | "Diagram" | "Proof" | "MCQ" | "Mixed";
  examSkill?: string;
  confidence: number;
}

interface GuidedProblemSolverRequest {
  problemId: string;
  normalizedProblemText: string;
  sourceRefs?: Array<{ type: "image" | "pdf" | "doc" | "text"; id: string }>;
  problemDNA: ProblemDNA;
  solvingMode: SolvingMode;
  interactionCount?: number; // only relevant for HELP_ME_SOLVE_IT
  userFollowUp?: string;
}

interface GuidedProblemSolverResponse {
  mode: SolvingMode;
  title: string;
  sections: Array<{ heading: string; bodyMarkdown: string }>;
  finalAnswer?: string;
  revealLevel: "hint" | "partial" | "full";
  interactionCount: number;
  followUpButtons: Array<{ label: string; action: string }>;
  citations?: Array<{ sourceId: string; label: string }>;
}

Safety and quality rules

  • Do not hallucinate source-specific facts. Use retrieved/cohort KB context where available.
  • Do not use unsafe shortcuts. Best Approach must prioritize reliability over speed.
  • Do not over-interact. Only Help Me Solve It can ask inputs, capped at 2.
  • Always show next actions. Every response ends with follow-up buttons.

08 · UI States

Frontend states to implement

These states make the flow feel stable and understandable.

Upload Processing

Show extraction status for image/PDF/doc. Disable solving mode selector until normalized problem text is ready.

DNA Loading

Show skeleton cards for chapter, difficulty, expected time, concept tags, and confidence.

Low Confidence DNA

If confidence is low, show “AI is not fully sure. You can still continue or edit detected subject/chapter.”

Mode Selected

Lock selected card visually while response streams. Allow changing mode after response via follow-up button.

Response Streaming

Stream sections progressively. Keep follow-up buttons disabled until stream completes.

Follow-up

Show buttons plus optional input box with placeholder: “Ask a follow-up, or choose an option below.”

09 · Acceptance Criteria

Definition of done

Use this checklist before developer sign-off.

  • Upload path works: text, image, PDF/doc inputs can produce normalized problem text.
  • Problem DNA appears before solution: subject/chapter/concepts/difficulty/confidence are shown first.
  • Step 3 displays exactly 4 solving modes: Explain from the Basics, Help Me Solve It, Show the Missing Idea, Show the Best Approach.
  • Mode affects response structure: each mode produces a visibly different output layout and follow-up buttons.
  • Help Me Solve It is capped: maximum 2 student input points; after that, the system completes or offers reveal options.
  • No full solution input required: the UI never depends on students typing equation-heavy working.
  • Best Approach is reliable: it does not prioritize risky shortcuts; it explains why the method is valid.
  • Every response ends with next actions: follow-up buttons are always present.
  • Events are persisted: mode selected, response, follow-up actions, and checkpoint inputs are stored.
  • Notebook continuity: session history should be available in the student’s notebook/problem-solving journey.
