mind map generation — grounding behavior audit

Two systems, two rules for what the map is allowed to see.

A side-by-side reading of how Google's NotebookLM grounds its mind map strictly in uploaded sources, against how ScholarSync's Studio pipeline currently decides between sources, chat, and highlighted text.

NotebookLM (verified, source-only)
ScholarSync (current implementation)

NotebookLM's rule is absolute: the mind map is generated strictly from uploaded sources. It never pulls from the internet, and it never pulls from chat history. Chat is a separate, source-grounded Q&A layer — the only bridge between the two is one-directional: clicking a map node can open a chat about that node, but nothing typed in chat ever feeds back into the map.

ScholarSync's rule is conditional: Studio automatically picks between three context modes — sources_only, chat_hybrid, selection_only — with no check for whether chat is actually substantial. A single short message is enough to make chat a primary input, fixed at ~60% of the model's focus, alongside a reduced ~40% slice of source material.

Net effect → NotebookLM: same sources always produce the same map. ScholarSync: the same sources can produce a different map depending on what was casually typed beforehand.
Case 01

One source, no chat — multiple concepts inside a single document

What happens when there's exactly one document and nothing has been said in chat yet — how does the system decide what's a "main" idea versus a "sub" idea?

● NotebookLM

Outline extraction from the document itself

Gemini reads the full text and performs concept extraction, identifying important concepts, topics, and how they relate to one another. It is effectively prompted to summarize the key topics and subtopics present in the material.

The document's own structure — headings, sections — acts as scaffolding. A central concept anchors the map (often the source title or overarching theme), and key ideas branch out from it as topic → subtopic.

Example: a single source on coral reef decline yields top-level nodes like "Ocean Acidification," "Rising Sea Temperatures," and "Pollution," each with further branches.

● ScholarSync

sources_only mode — broad retrieval, then synthesis

With no chat transcript present, Studio runs six fixed broad retrieval queries — overview, key concepts, examples, structure, relationships, processes — against the one selected source in Pinecone, merging results into a single context window.

The mind map prompt then performs the same kind of hierarchy decision NotebookLM makes — promoting some chunks to top-level branches, others to subtopics — but the candidate material is whatever those six queries happened to retrieve, capped at 28 chunks.

6 broad queries max 28 chunks 0% chat
Case 02

Multiple sources, no chat — concepts that repeat across documents

The harder case: several documents are uploaded, and the same concept may appear in more than one of them. Does it get merged, or duplicated?

● NotebookLM

Cross-referencing to find shared themes

The model reads across every document at once rather than producing one map per file. It cross-references multiple documents in the notebook to find common themes, revealing where sources intersect — and whether they agree or conflict.

A concept appearing in three different documents is merged into one node carrying the combined explanation, not duplicated three times. Each node stays linked back to the content that inspired it.

Verified example: 8 weekly lecture-slide sources produced 9 nodes total — one "Core Concepts" node aggregating themes from across all sources, the rest one per week.

● ScholarSync

Per-source balancing, then one integrated map

Retrieval is filtered strictly to the selected source IDs. For mind maps specifically (also flashcards), a balancing step reserves a minimum share of chunks per source before filling remaining slots by relevance score — so one well-scoring document can't crowd out the rest.

The mind map prompt explicitly instructs: multi-source synthesis — one integrated map, not two silos — directing the model to merge overlapping concepts into shared branches, conceptually mirroring NotebookLM's cross-referencing.

balanced chunks/source mind map + flashcards only quiz/slides: score-only, no balancing
Case 03

Sources plus a minimal chat — one short question

This is where the two systems genuinely part ways. A single short message exists in chat. Does it count, and how much weight does it get?

● NotebookLM

Irrelevant — chat is never part of generation

There is no equivalent decision to make. NotebookLM's mind map is never built from chat, regardless of how much or how little exists in it. A short question, a long thread, or total silence in chat all produce the identical map for the same set of sources.

The map only ever reflects the uploaded documents — it cannot be skewed by an offhand question.

● ScholarSync

chat_hybrid triggers instantly — no minimum bar

The instant any non-empty chat transcript exists alongside ≥1 selected source, the system switches modes. There is no length or quality threshold — one short message is sufficient. The transcript is then labeled primary, targeted at ~60% of the model's focus.

Source chunks drop to a supporting role at ~40%, which in practice caps near 11 chunks instead of the usual 28. The model is instructed to prioritize themes from the conversation and use sources only to fact-check — never to override the chat with a generic summary.

chat ~60% weight sources ~11 chunks (40%) no sufficiency check
Case 04

Sources plus rich, long chat

Now the conversation is substantial. Does either system shift its balance to lean further into chat — or does the ratio stay fixed?

● NotebookLM

Still irrelevant — same source-only rule applies

Chat volume has no bearing on map generation at all, by design. A rich, long chat thread produces exactly the same mind map as no chat, because the map was never reading the chat in the first place.

● ScholarSync

Same mode, same ratio — only the chat budget grows

The mode stays chat_hybrid; there is no separate "chat is now substantial" path. The only change is more conversation text entering the prompt, up to a 48,000-character cap before truncation — while the source allocation stays fixed at roughly the same ~11 chunks regardless of how much chat exists.

The instruction to the model is identical in the minimal-chat and rich-chat cases: prioritize the conversation's themes and goals; treat sources as supporting fact-checks only.

48,000 char chat cap ratio unchanged: 60/40
Case 05

Chat only — zero sources selected

No documents at all, just a conversation. Can a mind map be generated purely from what was said?

● NotebookLM

Not applicable to chat — sources required by design

NotebookLM's mind map button operates entirely on the notebook's uploaded sources. There is no concept of generating a map from chat alone — the feature's premise is summarizing source material, so it has nothing to fall back to without a document.

● ScholarSync

Blocked, except one narrow escape hatch

The Studio panel requires at least one selected source (or a valid NCERT/tutor scope) before generating anything — both sources_only and chat_hybrid need a source ID to even form a valid request, otherwise the API returns a 422/400.

The only path that works without a source is selection_only: the user highlights ≥15 characters directly in chat and picks a Studio action from the floating toolbar. Retrieval is skipped entirely — no Pinecone call happens — and the model is told to use only that highlighted excerpt, nothing else.

blocked by default escape: highlight ≥15 chars 0 Pinecone calls in selection mode

Where each system is fragile

NotebookLM's failure mode is input quality, not input source. Because grounding depends on finding shared themes across documents, unrelated files dumped into one notebook produce a messy, low-signal outline — the fix is keeping a notebook scoped to one clear goal. It also has a practical size ceiling: beyond roughly 40 nodes, a single map loses interpretability and should be split into several linked maps instead.

ScholarSync's failure mode is predictability. Because chat becomes primary the moment it's non-empty, a single throwaway message can pull the mind map's focus away from carefully retrieved, balanced source chunks — even though those chunks are still technically present in the prompt. The same set of sources can therefore produce a noticeably different map depending purely on what was casually typed beforehand, which is a guarantee NotebookLM's architecture never has to make or break.

● In one line — NotebookLM

For one source it extracts the concepts inside that document and ranks them into a topic→subtopic tree; for multiple sources it does the same thing but first cross-references every document to merge overlapping concepts into shared branches — and in both cases it stays grounded only in the sources, never the chat or the web.

● In one line — ScholarSync (current)

Chat becomes primary the instant it's non-empty (fixed 60/40 split regardless of length or quality), the system falls back to pure source retrieval only when chat is completely empty, multi-source balancing applies specifically to mind maps and flashcards, and generation is otherwise blocked unless a source is selected or text is explicitly highlighted from chat.
